Auditeur : OpenHands (agent). Périmètre : build, sécurité, structure, tests, état général du livrable.

## 3. OCR (Paddle) — résolu pendant l'audit

PaddleOCR est bien l'OCR prévu (`src/shared/ocr.ts` → moteur paddle, PP-OCRv5 mobile : det 4,7 Mo + rec 8,1 Mo + dict 2 617 o, 32 langues dont le français). Les poids ne sont PAS sous git (décision du contrat : 12,8 Mo jugé trop lourd) ; ils vivent au registre de packages GitLab `ocr-modeles/v2` et sont jugés par empreinte sha256 (`scripts/modeles-ocr.manifest.json`).

Constat initial : `resources/ocr/modeles/` vide → 1 échec unitaire (`test/unit/ocr-facture.test.ts`, `ModelesAbsents`) + gate `verify:etiquettes-dlc` rouge.

Résolution : poids rapatriés du registre (auth par jeton du projet), contrôlés par le juge officiel :
- `python3 scripts/verif-modeles-ocr.py` → **MODELES: 3/3 CONFORMES** (RC=0).
- `npx vitest run` → **158/158** (14 fichiers).
- `npm run verify:etiquettes-dlc` → **GARDE DLC/DDM: les 8 etiquetes rendent leur verdict (4 langues)**, moteur=paddle réel, RC=0.

Le moteur OCR est donc fonctionnel hors ligne, y compris les verdicts DLC/DDM multilingues (NL/FR).

## 5. Sécurité

- **Authentification : AUCUNE.** Mesuré : toutes les routes sont accessibles sans Authorization. Mitigations présentes : HOST 127.0.0.1, license middleware (usage commercial), rate limiter à budgets. **Recommandation n°1** : auth minimale (jeton local + session) avant toute exposition hors du poste.
- `npm audit` : **26 vulnérabilités (3 low, 4 moderate, 17 high, 2 critical)**. Critiques : `protobufjs ≤7.6.2` (exécution arbitraire, via onnx-proto ← onnxruntime-web ← @xenova/transformers et ppu-paddle-ocr), `tar ≤7.5.20` (écriture arbitraire, via node-gyp ← electron-builder — chaîne build/dev uniquement). High notables : `multer` (inutilisé dans le code → dépendance à retirer), `electron`, `pdfjs-dist`.
- Electron : `contextIsolation` actif — bon réglage.
- Secrets : `.env.example` propre (GEMINI_API_KEY placeholder, POMONA_USER/PASS vides) ; pas de secrets en dur détectés ; `.gitignore` exclut `*.db`, `*.env*`.
- Note : le jeton GitLab visible dans l'URL du remote `origin` devrait être remplacé par un credential manager (il figure en clair dans `git remote -v`).

## 7. OCR produit — défaut constaté (pleine page vs bandes)

Défaut réel du pipeline OCR facture : sur la pièce `test/banc/facture-synthetique.png` (1000×1240), l'OCR **pleine page** perd la ligne « Total HT … 419,60 » (sondes 9–17) alors qu'en **bandes horizontales de ~20 px + padding 13**, le même moteur la rend (sonde-18 : bande 713–734 → `["Total HT'", "419,60"]`, et les **7/7 attendus complets** sur 23 bandes). La variante sans trait décoratif (`sonde-12-sans-trait`) perd aussi la ligne : la cause n'est pas le trait mais la **segmentation de détection pleine page** (PP-OCRv5 mobile det).

**Remède prouvé** : pré-découpage en bandes (ou détection par zones) avant reconnaissance — à implémenter côté produit (`src/shared/ocr.ts`) pour l'extraction des totaux de factures. Les sondes 8–18 (`test/banc/`) documentent le cheminement.
